#CS 공부 -컴퓨터 구조

## 3. 핵심 부품 CPU
- 구성
1. ALU: 연산회로
2. 제어장치: 명령어 해석, 제어신호
3. 레지스터: 임시 저장장치

### 3-1. 레지스터 : 명령어 처리과정에서 해당 명령어는 실행 전후로 레지스터에 저장되기 때문에 개발자에게 중요한 부품
- 다양한 레지스터 존재
- 레지스터는 WinDbg, gdb 등의 디버깅 도구를 이용해 관찰 가능

#### 대표적인 레지스터
1. 프로그램 카운터 (PC) 메모리에서 다음으로 읽어들일 명령어의 주소를 저장
- 멸령어 포인터 (IP)라고 부르기도함
- 일반적으로 값이 1씩 증가 = 읽을 메모리 주소가 1씩 증가 / if, goto, 함수 호출 등에서는 PC값이 변동

2. 명령어 레지스터 : 해석할 명령어를 저장
제어장치 -> 명령어 레지스터 속 명령어 해석 -> ALU 연산/다른 부품 제어 신호

3. 범용 레지스터: 자유롭게 사용되는 레지스터(데이터,명령어,주소 저장 가능) 여러개 존재

4. 플래그 레지스터 : 연산결과, CPU상태에 대한 부가정보인 플래그 값을 저장
- 종류
1. 부호플래그: 연산결과의 부호
2. 제로플래그: 연산 결과가 0인지의 여부
3. 캐리플래그: 연산결과에 올림수나 빌림수가 발생했는지 여부
4. 오버플로우플래그: 오버플로우(저장값이 공간보다 클때 문제되는 것)이 발생했는지 여부
5. 인터럽트플래그: 인터럽트가 가능한지 여부
6. 슈퍼바이저플래그: 커널모드로 실행 중인지, 사용자 모드로 실행중인지 여부

5.스택 포인터: 메모리 내 스택 영역의 최상단 스택데이터 위치를 저장

#### 인터럽트(중요)
정의 : CPU의 작업을 방해하는 신호
- 동기 인터럽트 : CPU에 의해 발생하는 인터럽트
-- ex) CPU가 프로그래밍 오류와 같은 예외 상황에 마주쳤을 때 발생하는 인터럽트 = 예외(exception)이라고도 부름
- 비동기 인터럽트(하드웨어 인터럽트) : CPU가 효율적인 명령어 처리를 위해 사용하며 다른 HW, 주로 입출력 장치에 의해 발생하는 인터럽트
-- ex) CPU가 프린터에게 출력 작업을 부탁했을 때, 작업이 완료된 프린터기가 CPU에게 완료 알림(인터럽트)을 보냄
##### 인터럽트 처리 과정 (시스템콜,페이지폴트 등도 유사)
1. 입출력장치 ->* 인터럽트 요청 신호 -> CPU
2. CPU 실행사이클 종료 -> 인터럽트 여부 확인 -> 명령어 인출
3. 인터럽트 플래그를 통해 인터럽트를 받을 수 있는지 확인
4. 가능하다면 현재 CPU의 작업을 백업
5. 인터럽트 벡터를 참조하여 인터럽트 서비스 루틴 실행
6. 인터럽트 서비스 루틴 실행 -> 백업해둔 작업 복구 -> 실행 재개

- 인터럽트 요청 신호 : 인터럽트 가능한지 묻는 신호
- 인터럽트 플래그 : 플래그 레지스터의 인터럽트 플래그 활성
- 불가능하다면 요청 무시 - cf) 막을 수 없는 인터럽트 존재 (NMI = Non Maskable Interrupt)
- 인터럽트 서비스 루틴 (ISR) : 인터럽트를 처리하기 위한 프로그램(인터럽트 핸들러)
-- 인터럽트를 처리한다 = 인터럽트 서비스 루틴을 실행하고 본래 수행하던 작업으로 다시 되돌아온다는 의미
- 인터럽트 벡터 : 어떤 인터럽트인지 식별하기위한 내용으로 인터럽트 서비스 루틴의 시작주소가 주로 포함
- CPU 작업 백업 및 복구 : 스택영역으로 진행
-- 백업 : 프로그램 카운터, 레지스터 값( 스택포인터 등) 스택에 저장
-- 복구 : 저장한 스택의 정보를 복구

##### 예외(동기 인터럽트)의 종류
1. 폴트: ISR(인터럽트 서비스 루틴) 실행 복귀 후 예외 발생 명령어부터 실행
- 페이지폴트: CPU가 실행하려는 명령어가 메모리에 적재되지 않았을 때 보조기억장치에서 가져와야돼서 발생한 예외
2. 트랩: ISR(인터럽트 서비스 루틴) 실행 복귀 후 예외 발생 다음 명령어부터 실행
- 디버깅의 브레이크 포인트: 브레이크 지정 코드가 실행되는 순간 프로그램 중산 후 트랩이 처리되면 다음 명령어 실행
3. 중단: CPU가 프로그램을 중단시킬 수밖에 없는 심각한 오류를 발견했을 때 발생하는 예외
4. 소프트웨어 인터럽트: 시스템 콜이 발생했을 때 발생하는 예외

### CPU 성능 향상 방법
#### 하드웨어적 설계 방법
클럭속도 향상 및 멀티 코어 멀티 스레드
* CPU 클럭속도
클럭: 컴퓨터 부품이 동기화되어 움직이도록 하는 시간의 단위 (단위 Hz)
클럭속도: CPU의 속도 단위로 간주 but 클럭속도를 계속 올리면 발열이 심해진다.

* 코어: CPU 내에서 명령어를 읽어들이고 해석하고, 실행하는 부품 -통적인 관점의 CPU ->현대에서는 여러개의 CPU기능을하는 멀티코어가 가능해짐

* 스레드:
** 하드웨어적 스레드: 하나의 코어가 동시에 처리하는 명령어의 단위(집합)(논리 프로세서) 
*** 레지스터 세트: 하나의 명령어 처리에 마띵히 필요한 레지스터 집합. 레지스터 섹트가 여러개면 하나의 코어에서 여러개 명령어 흐름을 처리 가능
*** 레지스터 세트 = 스레드 수 = 운영가능한 명령어 흐름의 수
** 프로그래밍 언어 및 운영체제에서 사용하는 소프트웨어적 스레드 : 하나의 프로그램에서 독립적으로 실행되는 단위
** 1코어 1스레드 CPU로 여러개의 소프트웨어 스레드를 실행할 수 있다.

##### 멀티코어/멀티 스레드
- 병렬성 : 작업을 물리적으로 동시에 처리하는 성질
4코어 8스레드 CPU가 4개의 명령어를 동시에 실행
##### 소프트웨어 스레드
- 동시성 : 동시에 작업을 처리하는 것처럼 보이는 성질

#### 명령어 병렬 처리를 통한 성능향상

명령어 병렬 처리 기법 : 여러 명령어를 동시에 처리하여 CPU를 쉬지 않고 작동시켜 CPU 성능을 높이는 기법
- 대표 예시: 명령어 파이프라이닝, 슈퍼 스칼라

##### 명령어 파이프라이닝 -명령어가 처리되는 과정
- 비슷한 시간 간격으로 나눔
1. 명령어 인출
2. 명령어 해석
3. 명령어 실행
4. 결과 저장
- 같은 단계가 겹치치 않는다면 CPU는 각 단계를 동시에 실행 가능

##### 슈퍼스칼라
여러개의 명령어 처리 파이프라인을 이용하여 동시에 명령어를 처라힌다.
슈퍼스칼라 CPU = 슈퍼스칼라 프로세서

#### 파이프라인 위험 : 파이프라이닝으로 성능향상 실패 
1. 데이터 위험 : 명령어 간의 데이터 의존성에 의해 발생. 이전 명령어가 완수되어야 다음 명령어가 가능
2. 제어 위험 : 프로그램 카운터의 갑작스러운 변화에 의해 발생 -해결) 분기 예측
3. 구조적 위험 (자원 위험) : 서로 다른 명령어가 동시에 ALU, 레지스터 등 같은 CPU부품을 사용하려고 할 때 발생
