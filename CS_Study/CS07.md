#CS07 - 운영체제
## 2. 프로세스와 스레드

### 프로세스의 종류
1. 포그라운드 프로세스 : 사용자가 보는 공간에서 상호작용하는 프로세스
2. 백그라운드 프로세스 : 사용자가 보지 못하는 곳에서 실행되는 프로세스  
	1. 데몬 : 사용자 와 상호작용하지 않고 주어진 작업만 하는 특별한 백그라운드 프로세스(윈도우 운영체제 = 서비스)

-------------------------

### 프로세스 생성 및 실행 시 메모리에 저장되는 정보  
커널 영역 : 프로세스 제어 블록 PCB 저장  
사용자 영역 : 코드 영역, 데이터 영역, 힙 영역, 스택 영역으로 나뉘어 저장
--------------------------------------
사용자 영역은 정적 할당영역, 동적 할당영역으로 나뉘어진다.
- 정적할당영역
	- 코드 영역(텍스트영역) : 실행 가능한 명령어 저장 공간, CPU가 읽고 실행할 명령어(읽기 전용)
	- 데이터 영역 : 실행 내내 유지할 데이터(정적 변수, 전역 변수) 저장 공간
- 동적할당영역
	- 힙 영역 : 개발자가 직접 할당 가능한 저장공간, 할당하면 반환을 통해 메모리 누수 문제를 방지 해야함. 
		- 사용하지 않는 메모리를 해제하는 기술 = 가비지 컬렉션
	- 스택 영역 : 일시적 값(매개변수, 지역변수, 함수 복귀주소 등)들을 저장하는 공간
		- 특정 시점에 스택 영역에 저장된 함수 호출 정보 = 스택트레이스
------------------------------------------

#### PCB: 운영체제가 프로세스를 식별하기 위해 사용되는 구조체(정보 덩어리)

새로운 프로세스 생성 -> 메모리 적재 -> 커널영역 PCB 생성 -> 실행 종료 -> PCB 폐기
- PCB 공통 정보
	- PID : 프로세스 식별 고유 번호
	- 실행 과정에 사용한 레지스터 값
	- 프로세스 현재 상태 정보
	- CPU 스케줄링 정보(프로세스가 언제, 어떤 순서로 CPU할당을 받을지 우선순위에 대한 정보)
	- 메모리 정보 (메모리 상 적재 위치)
	- 프로세스 사용 파일 및 입출력 장치 관련 정보

프로세스 테이블 :여러 PCB들은 커널 내에서 관리되는 형태 = 실행 중인 PCB들의 모음  
실행 -> PCB -> 프로세스 테이블에 추가 -> 종료 -> 자원 해제 -> 프로세스 테이블에서 제거  
but 비정상적인 종료-> 자원 해제 -> 프로세스 테이블에는 PCB 존재 = 좀비 프로세스

---------------------------------------------

### 적재된 프로세스들이 어떻게 번갈아가며 실행되는가
- 짧은 사이 번갈아가면서 실행 = 프로세스마다  CPU 사용시간이 제한됨  
- 타이머 인터럽트 = 타임 아웃 인터럽트 : 운영체제가 현재 프로세스를 중단하고 다른 프로세스로 전환되도록하는 인터럽트
- 과정 : a프로세스 -> CPU 이용 -> 타이머 인터럽트 발생 -> 차례 양보
- 문맥 (context) : 자신의 차례가 끝나서 백업(중간 정보)한 정보
- 문맥은 PCB에 명시된다.
- PCB 문맥 복구 후 재개
- 백업 복구하며 번갈아가면서 실행되는 형태 =문맥 교환

### 프로세스 상태 : 프로세스가 처한 단계 정보
운영체제는 PCB를 통해 상태를 인식
- 생성 : 메모리에 적재되어 PCB를 할당받은 상태
- 준비 : 차례를 기다리는 상태/ 자원 할당 기다리는 상태  
디스패치 : 준비에서 실행 상태로 전환하는것
- 실행 : CPU 할당을 통해 실행 중인 상태
타이머 인터럽트 발생 -> 준비 상태로 전환  
입출력 요청/당장 확보 불가 자원 요청
- 대기 : 당장 실행이 불가한 상태
가능한 상황 ->준비 상태
- 종료 : 프로세스 종료 후 PCB와 프로세스가 사용한 메모리 정리  

cf)  
- 블로킹 입출력 : 입출력 잡업를 처리하기 위해 실행이 멈추는 처리 방식
- 논블로킹 입출력 : 입출력 요청 후 곧바로 명령어를 이어서 실행하는 처리 방식  
총 과정 : 프로세스 ->실행 -> 시스템 콜 -> 운영체제 -> CPU 장치 들아비ㅓ 코드 실행 -> 장치 컨트롤러 -> 장치

### 멀티프로세스와 멀티스레드 

#### 멀티 프로세스 : 여러개의 프로세스를 동시에 실행하는 것  
한 프로세스를 구성하는 코드를 나눠서 여러개의 각기 다른 프로세스로 실행할 수 있음  
ex) 웹 브라우저의 탭 : 1탭 = 1프로세스  
각기 다른 프로세스들은 기본적으로 자원 공유를 하지 못함 = 독립적으로 각각 자원을 할당 받음(PID, 별도 파일, 입출력 장치 등)

#### 멀티스레드 :  한 프로세스를 구성하는 여러 스레드를 동시에 실행하는 것  
스레드끼리 자원 공유 but 스레드 ID, 프로그램 카운터, 레지스터 값, 스택 등이 다를 수 있음  

멀티 프로세스 vs 멀티스레드
- 자원공유 : 
멀티 프로세스는 자원을 공유하지 않고 독립적으로 실행하여 한프로세스가 문제가 있어도 다른 프로세스에는 문제가 없을 수 있다.  
멀티 스레드는 같은 프로세스의 자원을 공유하여 스레드간 협력/통신에 유리하다. 그렇지만 한 스레드가 문제 있으면 프로세스 전체가 문제가 있을 수 있다.  

cf) 스레드조인   
join : 스레드 생성 주체가 생성/실행된 스레드가 종료될 때까지 대기해야 함을 의미  
ex) main스레드가 a스레드 생성 시 join호출 -> a종료까지 main은 실행되지 않고 대기  

#### 프로세스 간 통신 방법 = IPC
	- 1. 공통 메모리 : 프로세스가 통신할 수 있는 메모리를 통해서 자원을 주고받는 방식
	- 2. 메시지 전달 : 프로세스 간 데이터를 커널을 통해 메시지 형태로 주고받는 방식

- 1. 공통 메모리 : 프로세스는 이믜 메모리 공간을 수정할 수 없기 때문에 공유메모리라는 특별 공간을 할당 받아 해당 공간을 읽고 쓰며 사용
	- 방식
		- 1. 프로세스가 공유하는 메모리 영역 확보 시스템콜 기반으로 수행
		- 2. 프로세스가 공유하는 변수나 파일을 활용한 방식 (프로세스a : hi.txt 쓰기/ 프로세스 b : hi.txt 읽기 = hi.txt를 매개로 통신)

중요 특징 
- 프로세스가 자신의 메모리를 읽고 쓰는 것처럼 통신
- 데이터 주고받는 과정에 커널의 개입이 거의 없음

----------------------------------------------

- 2. 메시지 전달 : 데이터가 커널을 거쳐 송수신되는 방식  
	전달 시스템콜/ 수신 시스템콜을 활용  
	- 장점 : 커널의 도움 -> 레이스 컨디션, 동기화 문제를 덜 고려해도 됨
	- 단점 : 속도가 느림

- 메시지 전달 IPC를 구현 수단
1. 파이프 : 단방향 프로세스 간의 통신 도구  
cf) 익명 파이프 : 단방향 통신 수단 (전통적인 파이프). 부모-자식 통신 구조  
지명 파이프(네임드 파이프) : 익명 파이프의 확장된 방식, 임의의 프로세스 간 통신 가능  

2. 시그널 : 프로세스에게 특정 이벤트 발생을 알리는 비동기적인 신호 (IPC 뿐 아니라 다양하게 이용)  
시그널 핸들러 : 시그널 발생 시 처리를 위한 작업  
프로세스 a가 직접 특정 시그널 발생 -> 프로세스 b가 시그널 핸들러 재정의로 원하는 동작 수행 -> 직접메시지를 주고 받는 것은 아니지만 IPC 기법  
cf) 코어 덤프 : 비정상적으로 종료하는 경우 생성되는 파일로 어떤 시점, 어떤 메모리 상태에서 종료되었는지가 저장  

3. 원격 프로시저 호출(RPC), 네트워크 소켓 
- RPC : 원격 코드 실행 IPC 기술로 다른 프로세스 코드를 원격으로 실행   
	- 장점 : 성능 저하 최소화하여 메시지 송수신 ex) G RPC 프레임 워크 -> 대규모 트래픽 처리환경, 서버 간 통신에서 사용
- 네트워크 소켓 : 네트워크를 통한 프로세스 간 통신 기술
